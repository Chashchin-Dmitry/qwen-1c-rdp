# rdp-ai-1c

Обвязка, в которой открытая визуальная модель **Qwen3-VL** сама работает в Конфигураторе 1С через RDP: видит экран, кликает мышью, вставляет текст через буфер обмена. Файлы базы, SSH и доступ к серверу ей не нужны. На сервер ничего не ставится.

Так на тестовой реплике 1С:ERP были созданы шаблон URL, HTTP-метод и его обработчик, сделан бэкап расширения и обновлена конфигурация базы данных. Примеры этих заданий лежат в `tasks/examples/`, по ним удобно писать свои.

## Как это устроено

```
снимок экрана (agent-rdp)
      │
      ▼
ПЛАНИРОВЩИК  выбирает ОДНО действие: click / right_click / set_field / ...
      │
      ▼
НАВОДЧИК     даёт точку на экране (сетка 0–1000, при желании по вырезке ground_crop)
      │
      ▼
agent-rdp    кликает в RDP-сессии
      │
      ▼
ПРОВЕРЯЮЩИЙ  смотрит на новый снимок: подцель достигнута? да → следующая подцель
```

Все три роли может играть одна модель. Какую взять, задаётся в JSON задания.

Задание состоит из маленьких подцелей. У каждой есть `check`: что должно быть видно на экране после шага. Чем мельче подцель, тем надёжнее.

### Приёмы, которые пригодятся в своих задачах

- **`set_field`: ввод без клавиатуры.** Клавиатура от agent-rdp до Конфигуратора не доходит. Поэтому текст кладётся в буфер через канал RDP, дальше правый клик по полю → «Выделить все» → правый клик → «Вставить» → клик по соседней надписи, чтобы 1С приняла значение. Модель только говорит, какой текст и в какое поле.
- **`paste_text`: вставка кода в модуль.** Буфер, правый клик, пункт «Вставить» модель находит сама по вырезке вокруг меню.
- **`ground_crop`: зум для наводчика.** Наводчику показывают только область `[x1, y1, x2, y2]`, например строку меню. Так он перестаёт попадать в соседний пункт.
- **`verify_crop`: зум для проверяющего.** Область увеличивается ×2. Проверяющий на той же модели склонен отвечать «да», с вырезкой реже.
- **Предохранители.** Текст вводится только в подцелях с `"allow_type": true`. Клавиши из списка `ALWAYS_BLOCKED` (Ctrl+S, F7, Delete, Alt+F4, Win+R…) не отправляются, пока их нет в `allowed_keys` подцели. Есть лимит времени `max_total_s`. Файл `STOP` в папке скрипта останавливает прогон.

## Рецепт: от нуля до первого прогона

Всё ниже делается на рабочей машине с Windows, откуда вы и так ходите по RDP на сервер 1С.

### 1. Подготовить реплику и расширение

- Работаем **только в тестовой реплике** базы. Имя реплики должно заметно отличаться от боевой: агент читает заголовок окна, а человек в спешке тоже.
- Всё новое кладём в **отдельное расширение** (в примерах оно называется `api`) с префиксом `api_` у объектов. Основную конфигурацию не трогаем.
- Откройте Конфигуратор реплики в RDP-сессии и оставьте его открытым. Удобно держать дерево расширения отдельным окном справа: так написаны примеры.
- В настройках RDP-подключения выключите **проброс дисков и принтеров**. Агенту нужны только экран, мышь и буфер.

### 2. Бэкап `.cfe` до любых правок

Конфигуратор → «Конфигурация» → «Расширения конфигурации» → строка `api` → «Сохранить в файл…». Имя с датой, например `api_backup_2026-09-25.cfe`. Это можно поручить агенту (`tasks/examples/05_backup_cfe.json`), но имя файла в диалоге сохранения лучше ввести самому.

### 3. Поставить agent-rdp и Python-зависимости

```bat
npm.cmd install -g agent-rdp
py -m pip install -r requirements.txt
```

`npm.cmd`, потому что обычный `npm` в PowerShell блокируется политикой выполнения скриптов. agent-rdp: https://github.com/thisnick/agent-rdp

### 4. Поднять шлюз с моделью

Скопируйте `gateway/litellm.example.yaml` в `gateway/config.yaml` и выберите модель.

**Облако (так получен результат):** ключ Alibaba Model Studio (DashScope) в переменную окружения.

```bat
chcp 65001
set PYTHONUTF8=1
set LITELLM_LOCAL_MODEL_COST_MAP=True
set DASHSCOPE_API_KEY=ваш_ключ
set GATEWAY_KEY=придумайте_ключ_шлюза
litellm --config gateway\config.yaml --host 127.0.0.1 --port 4000
```

Если `litellm` не находится, он лежит в `%APPDATA%\Python\Python313\Scripts\litellm.exe`. `chcp 65001` и `PYTHONUTF8` нужны, иначе русские строки роняют шлюз в консоли cp1251.

**Локально через Ollama:** `ollama pull qwen3-vl:30b` (или `qwen3-vl:8b`) и в задании поставьте `"planner": "local-qwen3-vl-30b"` и т. д. Учтите: скриншоты Конфигуратора с именами объектов уходят в модель. Если это недопустимо, остаётся только локальная.

Проверить, что модель видит картинки и попадает в кнопки:

```bat
py tools\vision_probe.py cloud-qwen3-vl-plus local-qwen3-vl-30b
py tools\ground_test.py cloud-qwen3-vl-plus
```

### 5. Подключиться (пароль вводит человек)

```bat
set RDP_HOST=адрес_сервера_с_репликой
set RDP_USER=ваш_логин
scripts\ПОДКЛЮЧИТЬ.cmd
```

Пароль вводится в окне скрипта, в файлы не пишется. После пароля нажмите **Ctrl+Z, Enter**: так `--password-stdin` понимает, что ввод закончен.

Первое подключение может открыть **новую пустую сессию**. Чтобы agent-rdp подцепил сессию, где уже открыт Конфигуратор, закройте своё окно mstsc крестиком («Отключиться», не «Выйти») и подключитесь скриптом ещё раз. Смотреть, что видит агент, можно в браузере: http://localhost:9224

### 6. Взять пример задания и запустить

```bat
set GATEWAY_KEY=тот_же_ключ_шлюза
py qwen_rdp.py tasks\examples\01_open_method.json
```

Примеры идут по порядку, каждый продолжает предыдущий:

| Файл | Что делает |
|---|---|
| `01_open_method.json` | раскрывает шаблон `demo_status` и открывает его метод (разминка, ничего не меняет) |
| `02_create_template.json` | правый клик → «Добавить» → «Шаблон URL» |
| `03_set_template_props.json` | `set_field`: имя `api_test3p`, шаблон `/test3p` |
| `04_add_method.json` | метод GET и обработчик через «лупу»: 1С сама создаёт `Функция api_test3pGET(Запрос)` |
| `05_backup_cfe.json` | «Расширения конфигурации» → `api` → «Сохранить в файл…» |
| `06_save_and_update_db.json` | сохранить расширение и «Обновить конфигурацию базы данных» через главное меню |

Замените в них `demo_status`, `api_http`, `api_test3p` на свои объекты. Задания 01–04 работают в памяти Конфигуратора и ничего не сохраняют: откат = закрыть без сохранения. Задание 06 запускайте, только когда посмотрели результат своими глазами.

Каждый прогон пишет снимки и `run.log` в `runs_rdp/<время>_<имя>/`.

### Как написать свою подцель

Шаблон: `tasks/TEMPLATE.json`.

- **Одна подцель = один видимый шаг.** «Правый клик по узлу `api_test3p` в правом окне, в меню „Добавить“, в подменю „Метод“» работает. «Создай метод с обработчиком» проваливается.
- **Описывайте элемент так, как он выглядит**: текст, окно, положение. «Кнопка-лупа в правом конце поля „Обработчик“».
- **`check` должен быть виден на снимке**: заголовок окна, новый узел в дереве, значение в поле. Проверяющий ничего не знает, кроме картинки.
- **Мелкие иконки (16 px) и соседние пункты меню** требуют `ground_crop` на область меню. Длинные списки требуют подсказки «если не видно, прокрути».
- **Вместо горячих клавиш давайте меню.** F7 = «Конфигурация» → «Обновить конфигурацию базы данных», Insert = правый клик → «Добавить».
- **Вопросы 1С прописывайте в `rules` словами**: «на „Сохранить изменения?“ отвечай „Да“».

### 7. Проверить и откатить

- Проверка HTTP-метода: `GET http://<веб-сервер>/<публикация>/hs/<корень сервиса>/test3p` должен вернуть 200. Учётные данные вводите сами.
- Откат: «Расширения конфигурации» → `api` → «Загрузить из файла…» ваш `.cfe` → «Обновить конфигурацию базы данных». Или удалить созданный шаблон и функцию руками.

## Контур безопасности

- Только тестовая реплика, только своё расширение, бэкап `.cfe` перед каждой правкой.
- Пароли агенту не даются: RDP-пароль вводит человек, ключи лежат в переменных окружения.
- Решения «сохранить», «обновить БД», «опубликовать» принимает человек. Задание 06 запускается отдельно.
- RDP-сессия служит границей: агент получает картинку и отдаёт мышь и буфер. Внутри сессии у него права того пользователя, под которым вы вошли, поэтому реплика и бэкап обязательны.
- Облачная модель видит скриншоты. Для полностью закрытого контура нужна локальная модель.

## Известные проблемы

- **Клавиатура от agent-rdp до Конфигуратора не доходит** (даже Backspace), до Проводника доходит. Отсюда весь ввод через буфер и правый клик.
- **У Конфигуратора нет дерева UI Automation**, видна только рамка окна. OCR agent-rdp читает только латиницу. Агент опирается на картинку.
- **Смещения контекстного меню** в `set_field` измерены при 1920×1080 и масштабе Windows 100%. На другом разрешении задайте в задании `"menu_offsets": {"select_all": [x, y], "paste": [x, y]}`. Цель клика «для подтверждения» по умолчанию надпись «Комментарий» в окне свойств; для других окон задайте `"confirm_target"`.
- **Проверяющий склонен говорить «да»**, особенно если он та же модель, что и планировщик. Помогают `verify_crop` и конкретный `check`.
- **Длинные списки** (десятки расширений): модель может прокрутить весь список и не увидеть нужную строку.
- **Нет режима «только спросить».** На вопрос «что ты видишь?» планировщик начинает кликать. Для вопросов пока используйте модель напрямую.
- Строка `rdp("automate", "window", "focus", "Конфигуратор")` требует UIA-агент agent-rdp внутри сессии. Без него просто сделайте окно Конфигуратора активным перед запуском.
